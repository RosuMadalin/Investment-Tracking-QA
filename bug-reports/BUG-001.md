# BUG-001 — Chart range selector does not update the chart data

**Related test case:** TC-09 (`../test-cases/test-cases.md`)
**Status:** Open
**Jira:** [ITQ-2](../screenshots/jira-BUG-001.png) — Investment Tracking-QA project, currently in the `Failed` column ([board](../screenshots/jira-board.png))

## Summary
Changing the value of the "Select range" dropdown (1D / 5D / 1M / 6M / 1Y / 1W) has no effect on the displayed chart. The chart keeps showing data for the previously loaded range.

## Environment
- Browser: Chrome 129 (Chromium)
- OS: Windows 11
- Environment: Production — https://rosumadalin.github.io/tracking-tradings/#

## Preconditions
- Watchlist contains at least one symbol
- Charts view is open (via the **Charts** navbar button), so a chart is currently displayed

## Steps to Reproduce
1. Open the app and add a stock symbol to the watchlist (or use an existing one)
2. Click **Charts** in the navbar
3. Open the "Select range" dropdown and select a different value (e.g. change `1W` to `1M`)

## Actual Result
The dropdown's selected value changes, but the chart is not refreshed — it continues to display the data for the range that was active when the Charts view was opened.

## Expected Result
Selecting a new range should trigger the chart to reload with data for that range (functionally equivalent to calling `refreshCharts(range)` with the newly selected value).

## Root Cause (from source review)
`index.html` defines `<select id="chart-range">`, but no file in the codebase (`charts.js`, `index.js`, `navbar.js`, `watchlist.js`) attaches a `change` (or any) event listener to `#chart-range`. The `refreshCharts(range)` function in `charts.js` does accept a `range` parameter and is fully capable of loading the requested range — it is just never invoked with the dropdown's value.

## Severity
Major — a visible, advertised control that silently does nothing.

## Priority
High
